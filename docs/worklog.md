## 2026-08-27

**공유 링크가 결과 없이 초기 화면으로 가던 버그 수정** (실사용자 피드백으로 발견)
- `/celeb-match`, `/fox-type`, `/daily-charm` 세 페이지가 결과를 URL에 안 남기고
  React state/localStorage에만 들고 있어서, "공유하기"가 `window.location.href`를
  그대로 보내도 파라미터 없는 주소만 전달돼 친구가 링크를 눌러도 빈 입력 폼만
  보였음. 심테 결과 페이지(`?s=점수&n=닉네임`)와 같은 패턴으로 결과를 URL 쿼리에
  반영(`history.replaceState`)하고, 마운트 시 쿼리를 읽어 결과를 바로 복원하게 함.
  Playwright로 "결과 생성 → URL 캡처 → 새 탭에서 그 URL만 열기" 시나리오 검증 완료.

**Vercel `FIREBASE_CLIENT_EMAIL` 오설정으로 프로덕션 Firestore API 전체 장애**
- 사용자가 다른 프로젝트(OpenRouter) 작업 중 실수로 값이 바뀌어서, Firestore를
  쓰는 API 라우트가 전부 500(예: `/api/celebrity-image`)이었음 - 정적 페이지는
  멀쩡해서 발견이 늦어질 뻔함. 값을 바로잡고 재배포 후 정상화 확인.
  **교훈**: Vercel 환경변수는 대시보드에서 값만 바꾼다고 이미 떠 있는 배포에
  자동 반영되지 않음 - 반드시 재배포까지 해야 함.

**OpenRouter 키를 "여우점"(월 $10 한도) → "옥스알파"(무제한)로 교체**
- 이유: 요금 비교해보고 싶어서 + 기존 "여우점" 키는 한도가 있어서. 코드는 전혀
  안 건드림 - `lib/llm.ts`가 `OPENROUTER_API_KEY` 값을 그대로 갖다 쓰는 구조라
  어떤 키를 넣든 코드 변경 불필요. 모델(`deepseek/deepseek-chat`)도 키와 무관하게
  고정이라 안 바뀜(헷갈리기 쉬운 부분 - 키 교체 ≠ 모델 변경).
- 로컬 `.env.local` 교체 + 짧은 실제 호출로 키 유효성 확인(비용 $0.0000129,
  200 OK). Vercel 쪽도 값 교체 + Production 체크 + 재배포까지 사용자가 완료.
- **미검증 상태로 인계**: 프로덕션에서 실제로 새 키가 쓰이는지는 아직 확인 못함.
  AI 라우트(`/api/saju/llm-report`, `/chat`, `/fortune/[slug]/reading`)가 전부
  로그인 세션 필요라 비로그인으로 찔러볼 수 없고, 리포트 생성은 `reportId`가
  입력값(생년월일+성별+MBTI+이름) 기준 결정론적이라 **같은 입력이면 캐시된 리포트를
  그대로 반환하고 API를 새로 안 부름**(`app/api/saju/llm-report/route.ts:53`
  `status === "cached"`) - 그래서 예전과 똑같은 값으로 테스트하면 새 키 검증이
  안 됨. 검증하려면: ① 기존 리포트에 채팅 질문 새로 하나 남기기(채팅은 캐시 없이
  매번 API 호출) 또는 ② 생년월일/이름 중 하나를 바꿔서 리포트 새로 생성 - 둘 중
  하나로 정상 응답 오는지 + OpenRouter 대시보드에서 옥스알파 키 사용량이 찍히는지
  확인할 것.
